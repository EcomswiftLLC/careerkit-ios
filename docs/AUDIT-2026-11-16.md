# CareerKit audit, 2026-11-16

Scope: Apple App Store rules, Google AdMob rules, working features, design quality and competitor parity.
Method: code review by four audit passes, then fixes verified on GitHub Actions (macOS 26, Xcode 26, iOS 26 SDK): 490+ unit tests, UI screenshot runs on iPhone (light), iPad (dark) and iPhone in Spanish, French, German and Simplified Chinese.

## Verified by CI (green)
- Builds with Xcode 26 / iOS 26 SDK (required by Apple for uploads since 2026-04-28). Release build contains the production AdMob ids; CI fails if a Google test id ships in Release.
- All unit tests pass (496): renderer, 30 resume and 10 cover letter templates, style overrides, persistence and backup, ads gate and fallback, export formats (PDF, Word, Rich Text, text, HTML), job ad keyword match, resume import (including a PDF round trip), writing-assist guards, review prompt policy.
- Screenshots reviewed on iPhone 6.9" (light) and iPad 13" (dark): onboarding, home, My Resumes, templates, editor, style panel, ATS check with job match, import flow, export sheet with file type picker, profile.
- Localization (es, fr, de, zh-Hans): every string in the String Catalog has all four translations (CI test), placeholders match, the compiled app serves each language, and the Info.plist permission text is localized. Screenshots of Home, My Resumes, Templates, Cover Letters, Profile, editor, style panel and export sheet were reviewed in all four languages: no clipped labels or missing glyphs.
- Resume language: a resume can be written in a language other than the app's. Section headings, dates and "Present" follow it in PDF, Word, RTF and web exports. Every one of the 30 templates renders Chinese and German text and passes the PDF text check.
- Templates and photos: 30 templates with distinct layouts, 19 with a photo area (shape, size, border and side options, crop sheet). One-page and two-page sample length is checked per template.
- Bug found while testing Chinese and fixed: PDFKit returns some Chinese characters as radical code points (for example U+2ED3 for 长), which the text check and the PDF resume import did not match. Both now fold those radicals.
- Bug found by the audit and fixed: link rectangles in exported PDFs were not flipped into PDF page space, so email and web links missed their text.

## Apple rules
- No StoreKit purchases. StoreKit is imported in one file only, for the system review prompt (`Sources/App/ReviewPrompt.swift`), asked at most once per version after a finished export.
- UMP consent, then App Tracking Transparency, then ads. Privacy manifest and App Privacy answers are in `docs/store/app-privacy.md`. Delete-all-data is in Profile. No account needed.
- Apple Intelligence writing help is gated by availability, runs on device, and is hidden everywhere else.
- Not verifiable here: App Review outcome, real device consent and ATT prompts, VoiceOver on a device.

## AdMob rules
- Banners only on browse screens, inline and labelled "Advertisement", never on empty states, the editor, preview or export. Rewarded video is opt-in; reward granted only in the earned-reward callback; one unlock covers one export of one document for 24 hours.
- No interstitial or app-open ads. `maxAdContentRating` is general. If no video can be shown, the user can export without one, so exports never dead-end.
- Report-an-ad row and Ad privacy choices row in Profile.
- Not verifiable here: real ad fill (new units can have no fill for days), the UMP forms published in AdMob, blocking controls (owner steps below).

## Features vs competitors
Done: 30 distinct templates, full style customization, live preview, multiple resumes, cover letters, ATS guidance (no fake score), job ad keyword match, import from PDF or text, export to PDF, Word, Rich Text, plain text and web page, on-device AI writing help (Apple Intelligence devices), backup and restore, review prompt, iPad split editor, dark mode. No subscription, no watermark, no account.
Not built: translation of the sample resume text shown in template previews (English only), DOCX import, cloud sync. Recommended for 1.1: more languages (pt-BR, ar), undo and redo in the editor.

## Submission-readiness re-audit (second pass, same day)

Verdict: **the app itself is ready to be built, uploaded and submitted for App Review.** No code blocker was found. What remains is owner-side (accounts, listing, consent messages) and cannot be done from this repository.

Checked in this pass:
- Info.plist: bundle id, versions (1.0.0 build 1), portrait and landscape on iPhone, all four orientations on iPad (needed for multitasking), launch screen, `ITSAppUsesNonExemptEncryption` false, photo and tracking purpose strings present and localized in 5 languages, 50 SKAdNetwork ids.
- Privacy manifest matches `docs/store/app-privacy.md` row for row; required-reason APIs actually used (UserDefaults, file timestamps) are declared. Photos use the system picker, so no photo permission prompt appears. No location, camera, contacts or microphone code.
- No network code of the app's own (no URLSession, no web view). The only outside traffic is the Google ad SDK after consent.
- Debug-only code (screenshot seeding, test ad devices, consent reset) is inside `#if DEBUG`; none ships in Release. No TODO or placeholder text in the sources.
- Claims: ATS check and job match say they are guidance, not an employer score, and make no guarantees.
- Every UI name used in the App Review notes exists in the app (Watch an ad to export, Export without video, Ad privacy choices, Report an ad, Delete all local data, Skip, Export backup); the 20 second wait before the free-export fallback matches the notes.
- Store text: all five listings pass `design/check_store_metadata.py` (name 28/30, keywords within 100 bytes, no repeated words). App icons are 1024 px RGB without alpha. CI screenshots are exactly the required sizes (iPhone 6.9" 1320 x 2868, iPad 13" 2064 x 2752).
- Website: home, privacy, terms and support return 200, contain no draft notices ("coming soon" is intended until release).
- Fixed in this pass: `app-ads.txt` returned 404. It is now served at https://ecomswiftllc.github.io/app-ads.txt from the free user-site repo `EcomswiftLLC/ecomswiftllc.github.io` (AdMob can take up to 24 hours to show it as found). Stale lines in the submission checklist and a wrong keyword note in `metadata.md` were corrected. Spanish and French "paper size" labels shortened so the picker stays on one line.

Residual risks (cannot be removed from here):
1. Rewarded ads that unlock a feature are allowed, and the free-export fallback means a reviewer is never stuck. Real ad fill on new units is not guaranteed.
2. The name "Resume & CV Maker: CareerKit" is only confirmed available when the app record is created; fallbacks are in `metadata.md`.
3. The privacy policy and terms are drafts until a lawyer reviews them. Apple only needs a working policy URL, which exists.
4. Not testable without a device: the real consent and tracking prompts, VoiceOver, and real ad playback. Test on TestFlight with the owner's devices registered as AdMob test devices first.
5. After the first archive, open the Xcode privacy report and confirm it matches the App Privacy answers.
